## What is untested (sandbox cannot test these — Dell dogfood must)

- VS Code GUI: the panel, webview, activity-bar view, status bar,
  diff decoration, Accept/Reject, and Replay canvas have not been
  opened in VS Code. The extension host code compiles, but no VS Code
  API call has been exercised at runtime.
- Dell ports and proxy: port picking (11435/11436 held by Code.exe,
  expect 11437), the managed-PC proxy, and 127.0.0.1-only calls have
  not been exercised on the Dell. The port probe is socket code, not
  a Dell measurement.
- Warm serve and real model calls: no ollada serve was running in
  the sandbox, and no model was called. /api/chat request shape,
  fence stripping, checks on real model output, and timing have not
  been exercised end to end.
- Python extension API: interpreter discovery tries the ms-python
  API first, then workspace .venv, then PATH. That first branch has
  not been exercised without the Python extension installed.
- Serve child process: spawning, output channel, health polling,
  and the external PowerShell fallback have not been exercised.
- Replay with real snapshots: impossible on stock 0.3.4 by design.
  Only the disabled state and the step math are covered by tests.

## Deliberately disabled / out of scope

- Replay: disabled with "Replay not available for this model" on every
  stock 0.3.4 response (no snapshots field). No frames synthesized.
- Red model rows: no Download button. Dream and diffcoder on CPU:
  Needs a GPU, no button.
- Accept: never automatic; disabled if the file changed while ollada
  was working; one WorkspaceEdit, one undo step.
- Pip, pull, and serve: never without a click. Pip is never run by
  the extension at all.
- Everything in Phase 2–5 and the Phase 1 exclusion list: autocomplete,
  terminal commands run by the model, multi-file edits, agent loops,
  streaming, live animation, saved threads, persistent memory,
  remote/hosted serve, telemetry, bundled models, Marketplace publish.
- Geist font: not bundled. UI uses the VS Code font; code uses the
  editor font. Geist license check is still open before any publish.

## Dell dogfood steps (PowerShell-first, one command per block)

Prerequisites on the Dell: VS Code, Python 3.12 to 3.14, and a venv
with ollada 0.3.4. Do not taskkill Code.exe to free a port.

Step 1 — install from the Marketplace:

In VS Code, Extensions view, search ollada-code, publisher
OpenSourceRulesz, install 0.1.0 or newer. Do not transfer a .vsix
file for normal testing.

Step 2 — reload VS Code when prompted after installing.

Step 3 — make sure ollada is installed in the venv, with the server extra.
In a PowerShell terminal with the venv active, run:

```powershell
pip install "ollada[cpu,server]"
```

Step 4 — check the ollada version. In the same terminal, run:

```powershell
python -m ollada.cli --version
```

Expect 0.3.4 or newer. If it says 0.1.0, you are on Python 3.15:
switch to Python 3.12 to 3.14 first, then repeat step 3.

Step 5 — open the Ollada panel. Click the Ollada activity-bar icon,
or run the command `Ollada: Open Panel` from the Command Palette.
Setup should show, in order: Python, ollada, Pick a model, Start serve.
Nothing should download or start before you click.

Step 6 — pick a model. The picker should list models in recommend
order, one row per model, dream and diffcoder as separate rows.
sdar:1.7b should be Recommended / Runs on CPU. Click Download on
sdar:1.7b, watch the `Ollada: pull` terminal, and wait for Downloaded.

Step 7 — start serve. Click Start serve. The panel should say which
port it picked. With 11435 and 11436 held by Code.exe, expect 11437,
and nothing should be killed. The status bar should read
`Ollada: serving sdar:1.7b on 11437` (or whichever port it picked).

Step 8 — Fix, one file at a time. Open a Python file, select a single
broken function, click Fix selection. Check: the diff preview, the
checks row (Syntax, Undefined names, Dead code), the warning box, and
the time. Click Accept only after reviewing, and confirm the edit
lands as one undo step. Try Reject on one run and confirm nothing changes.

Step 9 — run the 9 script-test files through the UI and record, per file:
time, correct or not, checks pass or fail, and whether the warning box
showed. Expected from the script runs: 8/9 correct. The one failure,
find_max, must show checks passed plus the always-shown warning, not
a check failure — and running that function raises TypeError, which is
the point of the warning. Accept must never apply automatically.

Step 10 — try Explain selection and Insert at cursor, and report
quality honestly. Both prompts are proposed and untested, unlike Fix.
Insert writes at the cursor and does not read the code after the
cursor; API-level fill-in-the-middle is Phase 2 only.

Step 11 — try Watch diffusion on any answer. On stock 0.3.4, expect
the button disabled with "Replay not available for this model" for
every model. That is correct, not a bug. Real frames need a future
serve build with snapshots, which does not exist yet.

Step 12 — network check. In VS Code dev tools, confirm no network
request other than `127.0.0.1:<port>`.

Report back: for each step, what showed, what broke, the Ollada Serve
output channel log if serve failed, and the times for the 9 fixes.
If Setup shows a problem screen (Python too new, ollada missing,
server extra missing, serve not reachable), copy its exact title and
body — those screens are part of the test.

## Blockers that would change the spec

None found during this build that require a spec change. Two items
remain open exactly as the spec marks them, and were not closed by
assumption:

- Replay field shape (spec 6.7 / 10d): the extension sends
  `options.record_snapshots: true` and retries without options on
  rejection, but the serve-side shape is still a proposal. A real
  serve change is needed before Replay can be dogfooded with frames.
- UI font (spec 10c): Geist bundling and its license check are still
  open; 0.1.0 and 0.1.1 use the VS Code font, which is
  safe and native.
- Site install commands (spec 10a note): the live site still shows
  `pip install "ollada[cpu]"` / `"ollada[gpu]"` with a separate
  server command. Updating the site and README to `cpu,server` /
  `gpu,server` is a separate change through the usual rail, not this
  build, and was not done here.
